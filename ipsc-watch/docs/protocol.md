# Предлагаемый внутренний контракт v1

Это контракт модели, не реализованный Bluetooth-протокол.
Транспорт, кодировка, разбиение пакетов, handshake и аутентификация ещё не выбраны.

Каждое обновление — полный снимок, чтобы пропуск сообщения не терял выстрелы:

```json
{"version":1,"runId":"uuid-from-phone","sequence":2,"phase":"running","source":"timer","shots":[1250,1640]}
```

shots — строго возрастающие целые миллисекунды от старта. Максимум 1000 выстрелов,
время до 24 часов. sequence строго растёт внутри прохода. phase: running / finished.
До первого выстрела — running и пустой shots. Последний сплит считается по двум последним
выстрелам. Повторы, уменьшение счётчика и изменение уже принятых выстрелов отвергаются.

Новый runId принимается только после явного initialState(): будущий транспорт должен
реализовать надёжное событие начала/выбора прохода с подтверждением, чтобы задержанный
пакет старого прохода не заменял текущий. Автоматического сброса по таймауту нет.
source=demo не смешивать с source=timer. Передача не должна менять сохранённые проходы Android.
Нужны heartbeat и явное состояние потери связи; до реализации экран честно сообщает
«Нет подключения». При разрыве сохранять последнее время и отмечать устаревание данных.

Из пяти таймеров на часах отображать один выбранный поток. Выбор потока и связь с
назначениями в Android согласовать при интеграции; не смешивать выстрелы разных устройств.
