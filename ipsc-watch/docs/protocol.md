# Android ↔ Zepp ↔ часы — протокол 0.5 / 0.3

Устройство часов использует BaseApp/BasePage из официального @zeppos/zml; Zepp Side Service использует BaseSideService. Запросы часов IPSC_STATE и IPSC_COMMAND передаются уже связанной паре Zepp/часы. Поиск телефона через mstStartScan не используется.

## Локальный мост Android

- Слушает исключительно 127.0.0.1:19373, а не Wi-Fi/LAN.
- Все запросы: X-IPSC-Bridge: 1 и X-IPSC-Client с 32 шестнадцатеричными символами, созданными этой Side Service.
- GET /v1/state возвращает {session,packet}. packet — 20 байт ниже, session — случайный 128-битный идентификатор одобрения с телефона.
- До одобрения packet содержит только шестизначный код, никаких результатов. Пользователь визуально сверяет его на телефоне и часах.
- POST /v1/command: JSON {packet:[12 байт]} и X-IPSC-Session с текущей сессией. Нужны одобрение, совпадение клиента/сессии, возрастающий ID запроса. HTTP 202 подтверждает доставку, а не завершение команды. Dart отдельно проверяет проход, фазу, источник и доступность телефонного таймера.
- Прекращение heartbeat более чем на 6 секунд отзывает одобрение. Новый сеанс сбрасывает старые снимки на часах. Часы блокируют управление при данных старше 5 секунд.
- Строки/заголовки/тело HTTP ограничены по размеру, socket и выполнение запроса — по времени. Чужие клиенты и неизвестные пути отклоняются; CORS не включён. Запросы не отправляются внешним серверам.

## Снимок состояния: 20 байт, little endian

| Смещение | Поле |
| --- | --- |
| 0 | Версия 1 |
| 1 | Фаза: idle0, preparing1, running2, finished3, unavailable4; bit4 телефон, bit5 управление, bit6 ошибка |
| 2 | uint16 число выстрелов |
| 4 | uint32 идентификатор прохода; при revision0 — шестизначный код |
| 8 | uint32 revision; 0 только для кода |
| 12 | uint32 время последнего выстрела, мс |
| 16 | uint32 последний сплит, мс; ffffffff при числе выстрелов <2 |

## Команда: 12 байт

Версия1, операция start1/finish2, uint16 request ID, uint32 expectedRun, uint32 observedRevision. Все многобайтные поля little endian. Идентификатор сессии одобрения передаётся отдельно, чтобы старые команды не исполнились после повторного подключения.

Для внешнего таймера управление закрыто. Неизвестные outgoing-команды Special Pie не отправляются. Фоновый/закрытый телефонный таймер и несохранённый предыдущий проход блокируют новый запуск.

## Доставка завершения — 0.3.1 / Android 0.5.1

Нажатие завершения во время ожидания подтверждения старта запоминается и отправляется только для нового подтверждённого прохода. Для завершения допускаются два дополнительных повтора через интервалы не менее 1,5 секунды при свежих данных той же сессии и прохода. Повторный старт не выполняется. Уже завершённый проход отвечает повторному завершению без побочных действий. При смене прохода прежнее намерение завершения отбрасывается; старая команда не меняет новый проход.

## Постоянная пара (Android 0.7.0 / часы 0.5.0)

После одобрения текущего кода Android генерирует 32 случайных байта и сохраняет SHA-256 ключа вместе с client ID в закрытых настройках приложения. Ключ выдаётся текущему одобренному Side Service, сохраняется в settingsLib и передаётся заголовком X-IPSC-Trust только в loopback-запросах. В ответ watch RPC ключ не включается. При новом соединении ключ подтверждает сохранённую пару; session всё равно новый, старые команды не переносятся. Без верного ключа нужны новый код и одобрение. Команда forget удаляет доверие и текущую сессию.
